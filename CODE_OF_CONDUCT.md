# Code of conduct

## The short version

Be straightforward, be accurate, and assume the other person is competent.

## What that means here

This repository has one unusual house rule, and it is the one worth stating: **the
repo wins, and the document is the bug.** If you find a document that contradicts
the code, the document is wrong — say so, and fix it. Nobody is being criticised
when a claim is corrected; the claim is.

So:

- **Criticise the claim, not the author.** "This number is 60 out of date" is
  welcome. "You clearly didn't check" is not.
- **Say what you measured and how.** A disagreement about a number is settled by
  running the command, not by seniority.
- **"I don't know yet" is a complete answer.** This repo has a written convention
  for exactly that — `[P]` for proposed, with the open question attached.
- **Do not quietly drop a settled decision.** If a request conflicts with a
  decision the repo already made, name the collision. That is more useful than
  either silently complying or silently refusing.

## Scope

This applies to issues, pull requests, commit messages, code review, and any
project space — including the wiki, whose pages are generated from this repo.

## Reporting

Conduct problems go to **support@call-indigo.com**. Security problems have their own
channel — see [`SECURITY.md`](./SECURITY.md).
