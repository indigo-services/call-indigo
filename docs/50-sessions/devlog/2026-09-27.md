## What was asked

The request arrived in two parts, and the second superseded the first.

1. *"Analyze the entire project and produce a refactor plan for documentation under
   `/docs`… enhance the repo root README as the starting point and index of all project
   knowledge… make `/docs` the library and central link using the GitHub remote's wiki…
   Phase 1: create a PRD for the next release with a minimal scope, and PRDs for Phases
   2–5."*
2. Then, after an intermediate pass: *"let's proceed and complete all phases."*

Two clarifications changed the work materially:

- **"change to public repo with wiki enabled"** — the repository went public. That was
  presented first as a licensing risk (it contains template-derived assets) and the
  exposure was then measured and recorded rather than reversed.
- **"Not a single file from the template was used correct?"** — the first answer was
  **wrong**. It claimed the template was "copied substantially". The measurement said
  something narrower and more interesting, and the correction is recorded in §"What was
  tried and abandoned" below.

## What was tried and abandoned

> **The section that earns the devlog its place.**

- **"The template was copied substantially."** — **Abandoned because the measurement
  said something narrower.** The first answer to *"not a single file was used, correct?"*
  was wrong. Measured: the markup was **rewritten** (246 classes vs 488, 29 shared), and
  the CSS was **re-implemented** in Tailwind — but **59 images are byte-identical**, and
  2 MIT files had their notices stripped. **The honest statement is "inspiration plus 59
  verbatim images", not "a rewrite" and not "a copy".** This is the single most useful
  correction of the session, and it is why the repository has a rights register
  ([`../../60-reference/third-party-assets.md`](../../60-reference/third-party-assets.md))
  rather than a reassurance.

- **`gh api -X PATCH … -f has_wiki=true` to enable the wiki.** — Abandoned: `-f` sends a
  **string**, so the boolean was a no-op and the call returned `false` while reporting
  success. `-F` is the boolean form, and the authoritative field is GraphQL's
  `hasWikiEnabled`, not the legacy REST `has_wiki`.

- **Cloning `<repo>.wiki.git` before a first page exists.** — Abandoned: GitHub does not
  create the wiki repository until the first page is written, and there is **no API** for
  it. Resolved by the repository going public, at which point GitHub created `Home.md`
  itself.

- **Spawning a child process to read the HEAD SHA** in the sync script. — Abandoned:
  `execFileSync` cannot spawn **any** child process in this environment, on either Node
  version. Replaced with a `headSha()` that reads `.git` directly. The pushes run from
  bash instead.

- **A repo-wide scan for the stale claims.** — **Partially abandoned.** The scan found 5
  hits and **all 5 were legitimate quotations** — documents quoting the old claim in
  order to correct it. The check now uses a classified quotation allowlist, and that is
  the general lesson: *a scan for a string cannot distinguish an assertion from a
  quotation of one.*

- **Writing `127` into the documents.** — Abandoned deliberately, per the plan's F2
  analysis. Writing the new number **dates the defect**; the next round makes it wrong
  again. Every count now carries its producer, and the load-bearing ones are asserted.
